# Архитектура "Мобильный мир" - Проектная работа 4 спринта

## Описание проекта

Этот проект представляет собой решение для масштабирования и оптимизации микросервисной архитектуры онлайн-магазина "Мобильный мир". Проект включает в себя реализацию шардирования, репликации, кеширования, Service Discovery и CDN для повышения производительности и отказоустойчивости системы.

## Структура проекта

### Реализованные решения:

1. **mongo-sharding** - Базовая реализация шардирования MongoDB
2. **mongo-sharding-repl** - Шардирование + репликация для отказоустойчивости  
3. **sharding-repl-cache** - Полное решение с Redis кешированием (финальная версия)

### Архитектурные схемы (папка `schemes/`):

- **scheme1-sharding.drawio** - Шардирование MongoDB (2 шарда)
- **scheme2-sharding-repl.drawio** - Шардирование + репликация (по 3 реплики на шард)
- **final-scheme-sharding-repl-cache.drawio** - Итоговая схема: Шардирование + репликация + Redis кеширование
- **scheme4-service-discovery.drawio** - + Service Discovery (Consul) + API Gateway
- **scheme5-cdn.drawio** - + CDN для статического контента

> **Для проверки проекта используйте схему `final-scheme-sharding-repl-cache.drawio`** - она соответствует реализованному решению в папке `sharding-repl-cache`.

## Как запустить финальное решение

### Требования:
- Docker и Docker Compose
- Минимум 2 CPU и 4 ГБ ОЗУ
- Порты 8080, 6379, 27017-27039 должны быть свободны

### Запуск:

1. Перейдите в папку с финальным решением:
```shell
cd sharding-repl-cache
```

2. Запустите все сервисы:
```shell
docker compose up -d
```

3. Дождитесь запуска всех контейнеров (около 60 секунд):
```shell
docker compose ps
```

4. Выполните автоматическую инициализацию:
```shell
./scripts/init-sharding-repl-cache.sh
```

### Проверка работы:

1. Откройте в браузере: http://localhost:8080

2. Проверьте статус шардирования:
```shell
docker compose exec -T mongos mongosh --port 27017 --quiet <<EOF
sh.status()
EOF
```

3. Проверьте количество документов (должно быть ≥ 1000):
```shell
docker compose exec -T mongos mongosh --port 27017 --quiet <<EOF
use somedb
db.helloDoc.countDocuments()
EOF
```

4. Проверьте количество реплик (должно быть 3 для каждого шарда):
```shell
docker compose exec -T shard1-1 mongosh --port 27017 --quiet <<EOF
rs.status().members.length
EOF
```

5. Проверьте работу кеширования:
```shell
# Первый запрос (медленный)
time curl http://localhost:8080/helloDoc/users

# Второй запрос (быстрый <100мс)
time curl http://localhost:8080/helloDoc/users
```

## Компоненты системы

### MongoDB кластер:
- **configSrv**: Конфигурационный сервер
- **mongos**: Роутер запросов
- **shard1-1, shard1-2, shard1-3**: Первый шард с репликацией
- **shard2-1, shard2-2, shard2-3**: Второй шард с репликацией

### Кеширование:
- **redis**: Redis сервер для кеширования запросов

### Приложение:
- **pymongo_api**: FastAPI приложение с поддержкой кеширования

## Доступные эндпоинты

- `http://localhost:8080` - основное приложение
- `http://localhost:8080/docs` - документация API (Swagger)
- `http://localhost:8080/helloDoc/users` - кешируемый эндпоинт

## Особенности реализации

### Шардирование:
- Данные распределяются по полю `age` между двумя шардами
- Используется хеш-шардирование для равномерного распределения

### Репликация:
- Каждый шард имеет 3 реплики (1 primary + 2 secondary)
- Автоматический failover при отказе primary реплики

### Кеширование:
- Redis кеширует результаты запросов к эндпоинту `/helloDoc/users`
- Время жизни кеша настраивается в приложении
- Первый запрос выполняется медленно, последующие - быстро (<100мс)
